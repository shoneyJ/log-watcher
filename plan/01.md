## Haxe programming with C++ transpiler

How the toolchain works, front to back:

1. The **Haxe compiler** (`haxe`) type-checks `.hx` sources and, with the
   `--cpp <dir>` target flag, emits generated C++ sources into `<dir>`.
2. The **hxcpp** haxelib is the C++ backend runtime: it provides the headers,
   garbage collector, and the build tool (`haxelib run hxcpp`) that the
   compiler invokes automatically to compile the generated C++ with the
   system toolchain (g++ + make on Linux) into a native binary.
3. The result is a self-contained executable in the output dir — no Haxe
   runtime needed to run it.

Notes that matter for this project:

- The `sys.*` APIs (`sys.io.File`, `sys.FileSystem`, `Sys.sleep`) are fully
  supported on the C++ target — this is what the tail-and-poll loop of the
  log watcher will use.
- First C++ build is slow (hxcpp compiles its runtime once, then caches it);
  subsequent builds are incremental.
- Fast dev loop without the C++ compile: `haxe --interp` runs the program on
  the Haxe eval interpreter — same `sys.*` APIs work, so tail/parse logic can
  be iterated quickly there, with `--cpp` builds for verification.
- `-debug` builds keep line numbers for stack traces; add `-D HXCPP_DEBUGGER`
  only if a debugger is actually attached.

## System requirements

- Linux x86_64 (this machine: Ubuntu 24.04.3 LTS).
- C++ toolchain: `g++` and `make` — **already installed** (g++ 13.3.0).
  On a fresh machine: `sudo apt install build-essential`.
- Haxe 4.3.x + Neko (haxelib needs neko) — **not yet installed** here.
  Ubuntu 24.04's `apt install haxe` ships 4.3.x, which is sufficient;
  newer point releases are available from https://haxe.org/download/ if
  ever needed.
- hxcpp haxelib (installed per-project, see below).
- No other runtime dependencies: the produced binary only needs libc/libstdc++.

## How to setup development environment

```bash
# 1. Install the compiler toolchain (one-time, per machine)
sudo apt install haxe          # installs haxe + neko/haxelib

# 2. Project-local haxelib repo, so library versions are pinned to this
#    checkout (creates .haxelib/ — already gitignored). Run from repo root.
haxelib newrepo

# 3. Install the C++ backend into the local repo
haxelib install hxcpp
```

Proposed source layout and build entry point (create when coding starts):

```
src/Main.hx        # entry point
build.hxml         # compiler arguments, committed
```

`build.hxml`:

```hxml
--class-path src
--main Main
--cpp bin
```

Build and run:

```bash
haxe build.hxml    # emits C++ into bin/ and compiles it
./bin/Main         # run the native binary
```

Quick iteration without the C++ compile:

```bash
haxe --class-path src --main Main --interp
```

Editor support: VS Code + the `vshaxe` extension (uses the Haxe language
server bundled with the compiler; picks up `build.hxml` automatically).

Verify the setup end-to-end: after step 3, a hello-world `Main.hx` compiled
with `haxe build.hxml` should produce `bin/Main` that prints and exits 0 —
do this before starting on the watcher itself, since the first hxcpp build
also validates the g++/make toolchain.
